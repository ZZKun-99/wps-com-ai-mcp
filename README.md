# WPS COM AI MCP

让人和 AI 同时编辑同一个 WPS 文档。把该 MCP 挂到 AI harness 上，AI 就能借助 WPS 自带的 COM 接口，修改人当前已经打开、正在编辑的 Excel 或 Word 文件；读写的是内存里的实时状态，写完后默认不存盘，保存仍由人按 Ctrl+S。

## 功能

常见的做法是让 AI 把文件导出、改完再覆盖回去，人这边看不见过程，也撤销不了。该 MCP 把编辑放回人正在看的窗口里：连上的是人正在使用的 WPS 进程，可以列出当前打开的文档（含未保存的），再按应用执行读写动作。写动作默认不调用 Save，人可以用 Ctrl+Z 撤销，能盯着屏幕当场纠错、当场喊停。AI 绝不触发需要人工点选的 WPS 弹窗，也不关闭或退出人的窗口。

### COM 能力边界（已开发的部分）

Excel 侧最完整，读、写、查三类动作都在一个入口里：

- 读：`where` 看活动表状态（表名、已用区、数据列跨度、下一空行、合并区），`get` 按 `A1:C10` 之类的引用读值并附带合并区信息，`image` 把表格里的图落成文件、只返回路径与尺寸，图片本身不进上下文。
- 写：`set` 写值，`fill` 填背景色，`style` 改字体、对齐与数字格式，`width` / `height` 调列宽行高，`merge` / `unmerge` 合并与拆分单元格（写入前会先检查合并区，自动把值落到锚点），`brush` 只刷格式，`insert` / `delete` 增删整行整列，`clear` 可只清内容而保留格式与合并，`copy` / `move` 搬运或剪切区域（支持跨表，值不经模型上下文），`activate` 切换工作表，`save` 就地保存。
- 查：`find` 只回命中格的地址与数据，`replace` 一次做完查找替换；两者都支持正则、字面或整格、前后缀匹配，`replace` 必须给范围以免误替换整表。动作名还能带 `0` / `1` 后缀省字，例如 `copy1` 表示连格式一起复制、`replace1` 表示正则替换。

Word 侧目前只有整篇粒度的 `where`、`get`、`set`（可追加或整篇替换）和 `save`；PPT 侧保留 `where`、`get`、`save`，不改内容。边界也就在这里：Word 还没有段落级操作、查找替换和表格读写，PPT 不能写内容，写动作默认都不保存。工程里另有 24 个历史工具，默认不广播、无 schema，AI 看不到；`action="legacy"` 这个逃生口只放行读类，写类已全部拦掉。

## 实现方式

MCP 常驻时只向 AI 广播两个工具：`wps_docs` 只读列出打开的文档，`wps_do` 用 `app` + `action` + `args` 加一个可选的 `path` 统一执行动作。各动作的参数说明不写进常驻 schema，`tools/list` 仍是两个工具、约 755 字符，所以挂上却不用时几乎不占上下文。真要用的时候，让 AI 先调 `wps_do(app="excel", action="help")`，按需取回该应用的完整动作表和参数，这就是第二级加载。

动作实现都收在 `wps_session.py` 这层薄壳里，把 AI 常用的 COM 修改操作打包成统一入口：快速读取与写入、单元格合并、表格样式快速修改、格式刷、查找替换、跨表搬运都在一次调用里完成，图片和批量数据也只回摘要或路径。这样既减少了 COM 调用次数和来回轮次，也降低了 AI 侧写代码的复杂度，整体上更省 token、更省上下文。

底层用裸 `pywin32` + `comtypes` 做 COM 挂接，JSON-RPC over stdio 自己实现，没有引入官方 MCP SDK，也刻意没有用 `xlwings`（与 WPS 有兼容问题）。读操作走无按键旁路，永不发送 ESC；写操作先等人退出编辑态（默认 5 秒），仍冲突才发一个 ESC 把人从单元格编辑态挤出来，尽量不打断正在敲字的人。

## 使用注意事项

运行环境是 Windows 加 WPS Office（在 12.1.x 上验证，Microsoft Office 未测试）与 Python 3.8+。执行 `pip install -r requirements.txt` 即可，依赖为 `python-docx`、`openpyxl`、`python-pptx`、`pywin32`、`comtypes`；**不要装 `xlwings`**。把 `server.py` 的完整绝对路径写进 AI 客户端的 `mcpServers` 配置，`python` 不在 PATH 时也要换成 python.exe 的完整路径。配置好或改完代码都必须重启客户端，长驻进程不会自动重载；重启后让 AI 调一次 `wps_docs`，能列出打开的文档即接入成功。

人机共改的正确姿势是：人先用 WPS 打开文件并让它显示在屏幕上，再告诉 AI 文件路径和要改什么；AI 挂接到人正在看的窗口，写完由人自己按 Ctrl+S。人开着多本表又没指定 `path` 时，该 MCP 会报错并列出候选，让人指认。

有两类情况需要人到电脑前处理：WPS 弹出保存确认、另存为或只读提示时，程序无法自动点掉；明明开着文件却提示「目标文档不在其中」，多半是残留的 `et.exe` 占用了 COM 活动对象记录，结束该进程即可。

可调的环境变量有 `WPS_MCP_BUSY_RETRY_SECONDS`（写操作等编辑态退出的秒数，默认 5）、`WPS_MCP_BUSY_ESC`（设 0 关闭自动 ESC）、`WPS_MCP_READ_MAX_CELLS`（单次读取单元格上限，默认 200000）和 `WPS_MCP_SNAPSHOT_TTL_MS`（读快照 TTL）。`WPS_MCP_LEGACY_TOOLS` 与 `WPS_MCP_AUTOSAVE` 默认关闭，前者会暴露那 24 个老工具（其中有会清空整表并立即保存的实现），后者会让写操作自动保存、吃掉 Ctrl+Z，都不建议打开。
